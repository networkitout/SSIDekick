# WiFiUtil Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A macOS menu bar app that warns about evil-twin Wi-Fi access points and shows link quality and connectivity at a glance.

**Architecture:** One Swift package with three targets. `WiFiCore` is pure logic (models, twin detection, scoring, channel crowding, report text). `WiFiSystem` talks to macOS behind protocols and holds the `Engine` that drives everything, so it runs on fake data in tests and in demo mode. `WiFiUtil` is a thin SwiftUI `MenuBarExtra` app. A shell script assembles and signs the `.app` bundle.

**Tech Stack:** Swift 6.4, SwiftUI, CoreWLAN, CoreLocation, SystemConfiguration, UserNotifications, ServiceManagement, Swift Testing. No third-party packages.

**Spec:** `docs/superpowers/specs/2026-11-16-wifiutil-design.md`

## Global Constraints

- Minimum deployment target macOS 15. Apple frameworks only.
- Never change `xcode-select`. Every build and test command is prefixed with `DEVELOPER_DIR=/Applications/Xcode.app/Contents/Developer`. Below, `$T` means `DEVELOPER_DIR=/Applications/Xcode.app/Contents/Developer swift test`.
- Warn only: no code path may disconnect, join, forget or reconfigure a network.
- No private interfaces. No telemetry. Outbound traffic is limited to: gateway ping, DNS query to the configured server, `http://captive.apple.com/hotspot-detect.html`, and (if enabled) `https://api.ipify.org`.
- User-facing wording says "suspect" or "worth a look", with reasons. Never "safe", "secure" or "verified".
- A full scan runs only on: "Scan now", joining or changing access point, and the background interval (off, 30 s, 60 s, 5 min; default 60 s).
- `WiFiCore` imports only Foundation. It uses Swift 6 language mode; `WiFiSystem` and `WiFiUtil` use `.swiftLanguageMode(.v5)` because CoreWLAN types are not `Sendable`.
- No SwiftPM resources (their bundle lookup breaks inside a signed `.app`). Files the app needs at run time live in `Support/` and are copied into `Contents/Resources` by the build script.
- Bundle identifier `local.wifiutil.WiFiUtil`. Signing identity from `$SIGN_IDENTITY`, default `Apple Development`. Sign without hardened runtime.
- Fetching the IEEE vendor registry is a download: ask the owner before running `scripts/update-oui.sh`.

## Review Focus

1. **Names or addresses missing** (Location denied, hidden networks): access points with `ssid == nil` or `bssid == nil` are listed, never grouped, never crash detection. Test in Task 3.
2. **VPN connect or late IPv6 DNS arrival** must not raise "DNS changed": DNS and router are read for the Wi-Fi interface's own service, and the baseline settles for 10 s after joining. Tests in Tasks 4 and 8.
3. **Reconnect or sleep/wake onto a same-named network elsewhere** must not raise "gateway changed": baselines reset whenever the connection drops or the name changes. Test in Task 4.
4. **Ordinary multi-radio access points** (one device, several addresses differing in the low bits, 2.4 and 5 GHz, same vendor) must stay silent. Test in Task 3.
5. **Unusable system answers**: `arp` printing `(incomplete)` or unpadded octets, no IPv4 gateway on an IPv6-only network, a scan that throws because the radio is busy. Each yields "unknown" and keeps the last good data; none crashes or raises a finding. Tests in Tasks 1, 7 and 8.

**Interfaces — Produces:**

```swift
public enum Strength: Int, Sendable, Comparable { case weak, medium, strong }
public enum Signal: String, Sendable, CaseIterable {
    case securityMismatch, clonedAddress, gatewayChanged, dnsChanged          // strong
    case vendorMismatch, louderNewcomer, movedToFlagged                       // medium
    case locallyAdministered, countryMismatch, beaconMismatch, generationMismatch  // weak
    public var strength: Strength
}
public struct Finding: Sendable, Hashable {
    public var signal: Signal
    public var ssid: String
    public var bssid: MACAddress?   // nil = applies to the connection as a whole (gateway, DNS)
    public var reason: String       // one line, user-facing
}
public enum Verdict: Int, Sendable, Comparable { case clear, note, worthALook, suspect }
public func verdict(for findings: [Finding]) -> Verdict
public func networkVerdict(ssid: String, findings: [Finding]) -> Verdict
public struct TwinDetector: Sendable {
    public init(vendors: VendorLookup)
    public func findings(in scan: [AccessPoint]) -> [Finding]
}
```

Rules the tests do not fully determine:

- `verdict(for:)` scores one access point's findings: any strong → `.suspect`; any medium, or two or more weak → `.worthALook`; exactly one weak → `.note`; none → `.clear`.
- `networkVerdict` is the maximum of `verdict(for:)` over each distinct `bssid` (including `nil`) among findings with that `ssid`.
- Grouping is by exact `ssid`. Entries with `ssid == nil` or `bssid == nil` are skipped. "Siblings" of an access point are the other distinct addresses in its group.
- `securityMismatch`: its `weakestSecurity` is lower than the most common `weakestSecurity` among its siblings (ties resolve to the higher mode).
- `clonedAddress`: one address appears on two or more different channel numbers in this scan.
- `vendorMismatch`: its vendor is non-nil, at least two siblings share one vendor, and no sibling has its vendor. A nil vendor never raises this.
- `locallyAdministered`: it is locally administered and no sibling is.
- `countryMismatch`, `beaconMismatch`, `generationMismatch`: at least two siblings exist, all siblings agree on a non-nil value, and it differs.

**Files:**

**Interfaces — Consumes:** `Finding`, `Signal`, `AccessPoint`, `MACAddress`.

**Interfaces — Produces:**

```swift
public struct ConnectionState: Sendable, Hashable {
    public var ssid: String; public var bssid: MACAddress; public var rssi: Int
    public var gatewayMAC: MACAddress?; public var dnsServers: [String]
}
public struct ConnectionMonitor: Sendable {
    public init()
    public static let settleSeconds: TimeInterval = 10
    public private(set) var sessionID: Int      // increments each time a new session starts
    /// scan: pass a scan only when a new full scan has completed since the last call, else nil.
    public mutating func update(connection: ConnectionState?, scan: [AccessPoint]?,
                                siblingFindings: [Finding], now: Date) -> [Finding]
}
```

Behaviour:

- A session is continuous association with one `ssid`. `connection == nil` or a different `ssid` ends it and clears all baselines and findings. A change of `bssid` alone does not.
- The return value is every connected-session finding raised so far in this session (cumulative, de-duplicated by signal and address).
- Gateway baseline: the first non-nil `gatewayMAC`. A later different non-nil value raises `gatewayChanged` (`bssid: nil`). A nil value is ignored.
- DNS baseline: the `dnsServers` set as it stands `settleSeconds` after the session started; changes before then just move the baseline. An empty list is ignored. A later different non-empty set raises `dnsChanged` (`bssid: nil`).
- Newcomer baseline: the same-name addresses in the first scan passed during the session. In a later scan, a same-name address not in the baseline whose `rssi` is greater than `connection.rssi` raises `louderNewcomer` on that address.
- When `bssid` changes to an address that has any finding in `siblingFindings` or an existing `louderNewcomer`, raise `movedToFlagged` on it.

### Task 5: Channel crowding

**Files:**
- Create: `Sources/WiFiCore/ChannelCrowding.swift`
- Test: `Tests/WiFiCoreTests/ChannelCrowdingTests.swift`

**Interfaces — Produces:**

```swift
public func occupiedChannels(_ channel: Channel) -> [Int]
public struct ChannelLoad: Sendable, Hashable { public var band: Band; public var channel: Int; public var count: Int; public var strongestRSSI: Int }
public func channelLoads(_ scan: [AccessPoint]) -> [ChannelLoad]   // only channels with count > 0, sorted by band then channel
```

`occupiedChannels` algorithm:

- 2.4 GHz: every channel from `number − 4` to `number + 4`, clamped to 1...14, whatever the width.
- 5 GHz: segments `36...64`, `100...144`, `149...177`, channels 4 apart. Index within segment `i = (number − start) / 4`, block size `n = widthMHz / 20`, block start `i / n * n`; return the `n` channels of that block that exist in the segment. A number in no segment returns `[number]`.
- 6 GHz: one segment `1...233`, same maths. Width 320 is treated as 160.

`channelLoads` counts an access point on every channel it occupies.

```swift
    func publicIP() async -> String?
}
public protocol LocationAuthorizing: AnyObject {
    var isAuthorized: Bool { get }; var isDetermined: Bool { get }
    func request(); var changes: AsyncStream<Void> { get }
}
public struct EngineSettings: Sendable, Equatable {
    public var scanInterval: TimeInterval?   // nil = off; default 60
    public var publicIPEnabled: Bool          // default true
}
@MainActor @Observable public final class Engine {
    public init(wifi: WiFiSource, config: NetworkConfigSource, neighbors: NeighborSource, prober: Prober,
                location: LocationAuthorizing, vendors: VendorLookup, settings: EngineSettings,
                now: @escaping () -> Date = Date.init)
    public private(set) var snapshot: Snapshot
    public var settings: EngineSettings
    public var menuOpen: Bool                       // setting true triggers refreshPublicIP()
    public var onNewFindings: (([Finding]) -> Void)?
    public func start()                             // requests Location if undetermined; starts timers and event loops
    public func refreshLink()                       // link + state + location flag
    public func refreshProbes() async               // config, gateway MAC, ping, DNS, internet
    public func refreshPublicIP() async             // skipped when disabled or already cached for this session
    public func scanNow() async                     // full scan, then re-evaluate findings
}
public enum DemoScenario: String, CaseIterable { case office, planeTwin, clonedAddress, newcomer, gatewayChange, locationDenied, wifiOff }
public func demoSources(_ scenario: DemoScenario) -> (wifi: WiFiSource, config: NetworkConfigSource, neighbors: NeighborSource,
                                                      prober: Prober, location: LocationAuthorizing, vendors: VendorLookup)
```

Engine behaviour:

- `start()` seeds `snapshot.scan` from `wifi.cachedScan()` (not passed to `ConnectionMonitor` as a scan), then runs three loops using `Cadence` and `settings.scanInterval`, and reacts to events: `ssidChanged` and `bssidChanged` call `refreshLink()` then `scanNow()`; `changes` from config calls `refreshProbes()`.
- Every refresh ends by recomputing findings: `TwinDetector` over `snapshot.scan`, then `ConnectionMonitor.update` (passing the scan only right after `scanNow()`), then `NotificationLedger.pending`; non-empty results go to `onNewFindings`.
- `scanNow()` that throws keeps the previous `scan` and `scanTime`, and sets `scanError` to the error's description. A successful scan clears `scanError`.
- When `location.isAuthorized` is false, findings are empty and `connectedVerdict` is `.clear`.
- When `config.current().gatewayIP` is nil: `gatewayMAC`, latency and loss stay nil and no ping is sent.
- Public IP is cleared when `ConnectionMonitor.sessionID` changes.
- Loss comes from a `LossWindow` that resets with the session.

Demo sources: `newcomer` adds a louder same-name access point to scans made 10 s or more after creation; `gatewayChange` switches the neighbour answer after 15 s; the others are static. `planeTwin` is three same-vendor open "InflightWiFi" plus one different-vendor "InflightWiFi", connected to a legitimate one.

Decisions:

- `SystemNetworkConfig` uses `SCDynamicStore`. It finds the service whose `State:/Network/Service/<id>/IPv4` has `InterfaceName == interfaceName` and reads that service's `IPv4` (`Router`, `Addresses`), `IPv6` (`Addresses`) and `DNS` (`ServerAddresses`). It never reads `State:/Network/Global/DNS`, so a VPN does not change the answer. `changes` fires on notifications for `State:/Network/Service/.*/(IPv4|IPv6|DNS)`.
- `ARPNeighborTable` runs `/usr/sbin/arp -n <ip>` with a 2 s limit and passes stdout to `parseARP`.
- `icmpPing` uses `socket(AF_INET, SOCK_DGRAM, IPPROTO_ICMP)`, one echo request with an 8-byte header and 16-byte payload, timeout 1 s. The reply may or may not start with an IPv4 header: if the first byte's high nibble is 4, skip `(byte & 0x0F) * 4` bytes before reading the ICMP header. Accept only an echo reply (type 0) whose sequence number matches.
- DNS probe: UDP to port 53 of the server (IPv4 or IPv6), query name `apple.com`, random id, timeout 2 s; any response with the same id counts.
- Captive check: GET `http://captive.apple.com/hotspot-detect.html`, ephemeral `URLSession`, redirects not followed, timeout 5 s. `classifyCaptive`: status 200 with body containing `Success` → `.online`; any other response → `.captivePortal`; no response → `.offline`.
- Public IP: GET `https://api.ipify.org`, timeout 5 s, body through `validatedIP` (trim, must parse as an IPv4 or IPv6 address).
